# リソースフットプリント (FOOTPRINTS.md)

本ドキュメントは、低リソース環境（スペックの限られた Windows PC 等）における `MyNKF` の実測・推定フットプリント（バイナリサイズ、メモリ使用量、CPU オーバーヘッド）を記録するものです。

---

## 1. バイナリサイズ (Binary Size)

外部クレートおよび共有ライブラリへの依存を完全にゼロにし、Rust 標準ライブラリのみで構築した結果、極めて軽量な単体実行バイナリを維持しています。

| コンパイル構成                                                             | Windows バイナリサイズ (.exe)            | Linux バイナリサイズ | 備考                                                                     |
| :------------------------------------------------------------------------- | :--------------------------------------- | :------------------- | :----------------------------------------------------------------------- |
| `cargo build` (Debug)                                                      | 約 3.2 MB                                | 約 2.8 MB            | デバッグシンボルあり                                                     |
| `cargo build --release`                                                    | 約 290 KB                                | 約 260 KB            | 最適化あり                                                               |
| `cargo build --release` + `strip = true`                                   | 約 210 KB                                | 約 180 KB            | 不要シンボルの完全除去                                                   |
| `cargo build --release` + 最適化設定適用後 (2026-06-29)                    | **約 170 KB** (v1.2.0 以前 実測: 169 KB) | **約 140 KB**        | `[profile.release]` 全適用後の実測結果                                   |
| `cargo build --release` + ワイルドカード・サイズ表示機能追加後 (v1.4.0)    | **約 215 KB** (実測: 214 KB)             | -                    | 簡易グロブ展開およびファイルサイズ整形機能を追加した影響による増加       |

### バイナリサイズ削減のための推奨設定 (`Cargo.toml`)

製品版ビルドでは、以下の `[profile.release]` 設定を適用しています：

```toml
[profile.release]
opt-level = 'z'     # サイズ優先の最適化
lto = true          # リンク時最適化 (Link-Time Optimization)
codegen-units = 1   # 並列コード生成を無効化して最適化を最大化
panic = 'abort'     # パニック時のスタックトレース展開を無効化
strip = true        # デバッグシンボルとシンボルテーブルの自動削除
```

## 2. メモリ使用量 (Memory Usage)

- **静的メモリ (ベースオーバーヘッド)**: 約 500 KB 〜 1 MB（OS スレッドおよび Rust ランタイムの基本要件）
- **動的メモリ (バッファ処理時)**:
  - 入力ファイルが 10 MB の場合: 入力バイト列と変換後バッファを保持するため、概ね `入力サイズ × 1.5 〜 2.0` 程度の一時メモリで完結します。
  - `--guess` モードおよび改行変換のみモード（文字コード変換なし）では JIS マッピングテーブルや逆引き `HashMap` の構築を完全にスキップし、不要なメモリ確保を抑制しています。

---

## 3. CPU 負荷とパフォーマンス (CPU Overhead)

- **変換速度**:
  - 配列インデックスによる O(1) ルックアップ（デコード）および `HashMap` による O(1) 逆引き（エンコード）、さらに改行単独変換時のバイト列直接置換により、大容量ファイルでも低スペック CPU 上で高速に処理が完了します。
- **ディスク I/O**:
  - `File::read_to_end` および `io::stdout().write_all` による一括バッファ入出力を採用し、細切れのシステムコール呼び出しを抑えて安定したスループットを確保しています。
