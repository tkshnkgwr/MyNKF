# 仕様書 (SPEC.md)

本ドキュメントは、低リソース環境向けに最適化された CLI ユーティリティ `MyNKF` の最新の機能仕様を定義するものです。

---

## 1. 概要

`MyNKF` は、伝統的な日本語文字コード変換ツール `nkf` (Network Kanji Filter) の機能を、100% Rust 標準ライブラリ（`std`）のみでエミュレートした軽量なコマンドラインユーティリティです。外部依存ライブラリ（Crates）を一切持たず、セキュリティ、ポータビリティ、およびリソース消費（CPU、メモリ、バイナリサイズ）に極限まで配慮して設計されています。

---

## 2. 動作環境・制約

- **ターゲットOS**: Windows 10 / 11（低リソースPCを想定、Rustビルドはクロスプラットフォーム動作可能）
- **依存関係**: 外部クレート依存なし (純粋な Rust `std` のみ使用) でビルド可能。
- **バイナリサイズ目標**: `cargo build --release` 時に `strip` オプション等を適用し、約 200KB〜250KB。
- **メモリ使用量**: 数MB以下（ストリームまたはバッファ処理）。
- **処理ファイル数制限**:
  - メモリやCPUへの過度な負荷を防止するため、一度に処理可能なファイル数は最大 **100ファイル**（ワイルドカード展開後を含む）に制限されます。上限を超えた場合はエラーを出力して終了します。

---

## 3. CLI コマンド仕様

### 3.1 起動引数と構文

```powershell
MyNKF [options] [file...]
```

### 3.2 サポートするオプション

| オプション | エイリアス              | 説明                                                                                                                                  |
| :--------- | :---------------------- | :------------------------------------------------------------------------------------------------------------------------------------ |
| `-w`       | `--utf8`                | 出力を UTF-8 に変換する。改行コードは原則 `LF`。                                                                                      |
| `-s`       | `--sjis`                | 出力を Shift_JIS に変換する。改行コードは原則 `CRLF`。                                                                                |
| `-e`       | `--euc`                 | 出力を EUC-JP に変換する。改行コードは原則 `LF`。                                                                                     |
| `-g`       | `--guess`               | 指定されたファイル、または標準入力の文字コードを判定し結果を表示する。                                                                |
|            | `--line`                | 自動判定（`--guess`）モード時、テキストの論理行数も併せて表示する（`BINARY` を除く）。                                                |
|            | `--size`                | 自動判定（`--guess`）モード時、フォーマットされたファイルサイズも併せて表示する（例: `[1.2 KB]`, `[100 B]`、`BINARY` の場合も表示）。 |
| `-d`       | `--lf`                  | 改行コードを強制的に `LF` に変換する。                                                                                                |
| `-c`       | `--crlf`                | 改行コードを強制的に `CRLF` に変換する。                                                                                              |
| `-h`       |                         | 簡潔なヘルプテキストを表示し、終了する。                                                                                              |
|            | `--help`                | 詳細なヘルプテキスト（各オプション詳細および使用例）を表示し、終了する。                                                              |
| `-v`       | `--version`, `--versio` | バージョン情報 (`v1.6.5`)、著作権およびライセンス情報を表示し、終了する。                                                             |

> [!NOTE]
> `--versio` （最後の `n` が欠けた形式）は、本家 `nkf` のコマンドライン引数解析の挙動（独自パーサーによる前方一致のエミュレーションや歴史的なタイポの救済措置）と完全に一致させるために定義されている互換オプションです。

- **文字コード指定オプションが無い場合の挙動 (改行コードのみの変換)**:
  - 文字コード変換オプション（`-w`, `-s`, `-e`）のいずれも指定しなかった場合は、再エンコードを行わずバイト列レベルで直接改行置換（`convert_line_endings_raw`）を実行し、入力データの文字コードをそのまま維持します。
  - これにより、`-d` (LF) または `-c` (CRLF) オプションのみを指定した際、入力のエンコーディングを変更することなく、改行コードのみを無劣化で変更して出力することができます（本家 `nkf` 準拠）。
- **重複オプション指定時の優先順位**:
  - `-w` / `-s` / `-e` や `-d` / `-c` を複数回指定した場合は、後に指定されたオプションが優先（後勝ち）されます。
- **ファイル引数の省略**: ファイルパスが省略された場合は、標準入力 (`stdin`) を対象とし、処理結果を標準出力 (`stdout`) に送ります。
- **複数ファイル指定とエラー時の終了コード**: 複数のファイルを引数に渡した場合、各ファイルが順番に処理されて標準出力へ出力されます。存在しないファイル等で読み込みエラーが発生した場合は標準エラー出力へ通知して残りのファイルを処理し、最終的に終了コード `1` で終了します。
  - **ワイルドカード対応**: 引数にはワイルドカード（`*`、`?`）を使用できます（例: `MyNKF --guess *.txt`）。Windowsの標準コマンドプロンプトやPowerShell環境など、シェルによる展開が行われない環境においても、プログラム自身が簡易的なグロブ展開を行います。
  - **最大件数制限**: 安全のため、展開後の合計ファイル数が **100ファイル** を超える場合は、エラーを表示して終了コード `1` で処理を即座に中断します。

## 4. 文字コード変換および判定ロジック

### 4.1 自動判定（Guess）

入力バイト列を走査し、以下の手順およびエンコーディング特徴量のスコアリングに基づいて文字コードを推定します。

1. **空データ**: 0バイトの場合は `ASCII` と判定します。
2. **制御文字チェック (`BINARY`)**: ヌル文字（`0x00`）やバイナリ特有の制御文字が含まれている場合、即座に `BINARY`（`Encoding::Unknown`）と判定します。
3. **ASCII**: すべてのバイトが `0x00`〜`0x7F` の範囲内にある場合、`ASCII` と判定します。
4. **UTF-8**: `std::str::from_utf8` による厳格な検証を通過した場合、`UTF-8` と判定します。
5. **Shift_JIS / EUC-JP スコア比較**: Shift_JIS（2バイト文字・半角カナ `0xA1..=0xDF`）と EUC-JP（2バイト文字・半角カナ `0x8E`・補助漢字 `0x8F`）の構文妥当性と JIS X 0208 区点範囲（1〜84区、1〜94点）の重み付けスコアを比較して判定します（双方妥当かつ同点時は `Shift_JIS`）。
6. **BINARY**: 上記いずれのテキストエンコーディングのルールにも適合しない場合、`BINARY` と判定します。

#### 自動判定出力フォーマット

自動判定（`--guess`）時の出力は、入力データおよびオプションの有無により以下のように変化します。

- **`BINARY` の場合**:
  改行コードおよび行数の追加表示は行いません（ファイルサイズは表示可能です）。

  - 標準入力: `BINARY`
  - 標準入力（`--size` あり）: `BINARY [1.2 KB]`
  - ファイル指定時: `file.bin: BINARY`
  - ファイル指定時（`--size` あり）: `file.bin: BINARY [1.2 KB]`
- **`BINARY` 以外（テキスト）の場合**:
  判定された改行コード（`LF` / `CRLF` / `CR` / `MIXED` / `NONE`）を併記します。`--line` 指定時は論理行数、`--size` 指定時はファイルサイズがそれぞれ併記されます。

  - 標準入力: `UTF-8 (LF)`
  - 標準入力（`--line` あり）: `UTF-8 (LF) [123 lines]`
  - 標準入力（`--size` あり）: `UTF-8 (LF) [1.2 KB]`
  - 標準入力（`--line` と `--size` あり）: `UTF-8 (LF) [123 lines] [1.2 KB]`
  - ファイル指定時: `file.txt: UTF-8 (LF)`
  - ファイル指定時（`--line` あり）: `file.txt: UTF-8 (LF) [123 lines]`
  - ファイル指定時（`--size` あり）: `file.txt: UTF-8 (LF) [1.2 KB]`
  - ファイル指定時（`--line` と `--size` あり）: `file.txt: UTF-8 (LF) [123 lines] [1.2 KB]`

### 4.2 マッピングと外字フォールバック

- **JIS X 0208 基準のマッピング表**: JIS X 0208 全6,953文字に対応するマッピングテーブルを Base64 形式でバイナリ内に埋め込んでいます。
- **半角カタカナの保持**: Shift_JIS の `0xA1`〜`0xDF`（半角カタカナ）は、UTF-8 や EUC-JP の対応するコードへ正しくマッピング変換され、喪失しません。
- **フォールバック**: マッピングが定義されていない外字・絵文字・サロゲート外文字（`U+10000` 以上）が検出された場合、エラーにせず `??`（2つのクエスチョンマーク）に置換して処理を継続します。
