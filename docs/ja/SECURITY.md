# セキュリティポリシー (SECURITY.md)

本文書は、`MyNKF` プロジェクトにおけるセキュリティ方針および脆弱性報告手順をまとめたドキュメントです。

---

## 1. セキュリティ設計と安全性

`MyNKF` は以下の設計原則により、高いセキュリティと信頼性を保証しています。

1. **外部依存ゼロ (CLI版)**:
   - CLI版（`mynkf`）は外部クレートを一切依存関係に含まないため、サプライチェーン攻撃やサードパーティライブラリの脆弱性の影響を受けません。
2. **依存最小化と直接 FFI (GUI版)**:
   - GUI版（`mynkf-gui`）についても、UI描画用の `eframe/egui` や `rfd` 等の最小限のクレート以外は依存せず、Windows API については `windows-sys` などの巨大クレートを導入せず直接 FFI 呼び出しを行って検証されたスコープのみで記述されています。
3. **メモリ安全性**:
   - Rust 言語の強力な所有権システムと型安全性を活用し、メモリ安全性上の脆弱性（バッファオーバーフロー、ヌルポインタ参照等）を排除します。
4. **ローカル完結型の動作**:
   - ネットワーク通信を一切行わず、純粋にローカルファイルシステムの文字コード変換処理のみを行います。

---

## 2. サポートされるバージョン

以下のバージョンに対してセキュリティアップデートが提供されます：

| バージョン | サポート状況 |
| :--- | :---: |
| 最新リリース (`v1.5.x` 以上) | ✅ サポート |
| 古いリリース | ❌ 非サポート |

---

## 3. 脆弱性の報告方法

`MyNKF` に潜在的なセキュリティ脆弱性を発見された場合は、公開 Issue を作成するのではなく、以下の手順でご報告ください。

1. **報告窓口**:
   - リポジトリの管理者に直接ご連絡いただくか、セキュリティ報告用窓口へメールを送信してください。
2. **記載いただきたい内容**:
   - 影響を受ける `MyNKF` のバージョンとOS環境
   - 脆弱性の詳細と再現手順（概念実証コードまたはコマンド例）
3. **対応プロセス**:
   - 報告を受領後、速やかに受領確認を行い、修正パッチを作成・検証したうえでリリースを行います。
